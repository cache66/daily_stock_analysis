# QUANTAXIS 源码深挖记录
最后更新：2026-04-27

## 1. 仓库定位

`QUANTAXIS` 的公开定位一直比较鲜明：它是一套偏 A 股本地化、偏“数据 + 回测 + 账户 + 任务”一体化的量化基础设施框架。

对我们最重要的判断是：

- 它最强的不是今天就能替我们做出更好的主选股策略
- 它最强的是 A 股本地化底座、任务化组织、统一账户与本地数据体系思路
- 它最适合作为我们未来“本地数据底座、任务组织、A 股基础设施层”的参考对象

本轮结论基于 2026 年 4 月官方公开仓库与仓库内文档说明：

- 官方 GitHub 仓库：<https://github.com/yutiansut/QUANTAXIS>

## 2. 核心结构与入口

本轮优先看的真实入口包括：

- 仓库主页 README
- `QASU`、`QAFetch`、`QAUtil` 等模块说明
- `QIFI / QAMarket` 统一账户说明
- 2.1 alpha 相关架构说明

可以先把它理解成 5 层：

1. 数据获取与更新层
   - `QAFetch`
   - `QASU`
2. 工具与基础设施层
   - `QAUtil`
   - 日历
   - 市场识别
   - 本地任务支持
3. 账户与市场层
   - `QIFI`
   - `QAMarket`
4. 回测与仿真层
   - 账户回放
   - 回测
5. 新版桥接与性能层
   - `QARSBridge`
   - `QADataBridge`

## 3. 真正的优点

### 3.1 它非常懂 A 股本地化基础设施问题

QUANTAXIS 的价值，不在于它是不是“最现代”的量化框架，而在于它长期围绕 A 股本地化问题组织能力。

这包括：

- 本地数据组织
- 市场识别
- 交易日历
- 账户与市场语义
- 多任务运行

这和很多偏美股、偏通用金融平台的项目不同。

### 3.2 它更像“本地量化底座”，不是单点策略项目

QUANTAXIS 最值得借的，不是某个策略脚本，而是它长期试图把下面这些层放在一起：

- 数据
- 工具
- 账户
- 回测
- 任务

这对我们很有意义，因为我们当前也在逐步意识到：

- 单脚本优化的上限很快就到了
- 真正支撑长期演化的，是本地底座是否清楚

### 3.3 它的统一账户思路值得看

`QIFI / QAMarket` 这类设计的价值在于，它试图统一：

- 账户状态
- 市场接口
- 策略与执行之间的交互语义

对我们当前虽然不是第一优先级，但对后续组合层和模拟层有参考意义。

### 3.4 它最近的桥接层设计说明它在补性能与工程问题

仓库 README 中对 `QARSBridge / QADataBridge` 的强调，说明 QUANTAXIS 也在正面解决：

- 性能
- 数据交换
- 底层桥接

这和我们最近在本地策略里遇到的扫描性能问题，是同一类工程问题。

## 4. 我们能直接用的能力

### 4.1 把它当“A 股本地底座”参考对象

这是它对我们最直接的价值。

特别适合服务我们的：

- 市场与代码识别
- 交易日历
- 本地数据组织
- 本地任务化运行

### 4.2 借它的数据与工具层分离方式

QUANTAXIS 的一个重要提醒是：

- 数据获取
- 数据更新
- 工具函数
- 策略运行

应该显式分层。

这对我们当前继续收口数据层很有帮助。

### 4.3 借它的本地任务化思路

我们现在很多扫描与补数任务，已经开始显露出“脚本多、调度散、执行不统一”的问题。

QUANTAXIS 更适合作为提醒：

- 本地量化系统需要任务化组织
- 不只是“再写一个脚本”

### 4.4 给未来组合和模拟层提供本地语义参考

虽然我们现在不着急推进账户层，但 QUANTAXIS 的统一账户、市场、模拟语义，适合作为以后补：

- 组合层
- 模拟层
- 风险层

时的 A 股本地参考。

## 5. 只适合参考、不建议直接接入的部分

### 5.1 不建议把 QUANTAXIS 当当前主策略引擎

它的价值主要在基础设施，不在今天就替我们做：

- `trend_leader_unified`
- `earnings_surprise`

这些主策略判断。

### 5.2 不建议直接整套引入其本地生态

QUANTAXIS 本身覆盖面很广，直接引入会让我们的系统复杂度快速上升。

更合理的是：

- 借其本地底座思想
- 保留我们自己的策略和字段口径

### 5.3 不建议高估它对当前短线收益问题的直接帮助

它更像基础设施补强对象，而不是绩效立刻提升对象。

## 6. 不建议引入的部分

### 6.1 不建议为了 A 股本地化而一次性重做数据底座

当前更合理的是逐步对齐：

- 代码语义
- 日历语义
- 本地任务组织

### 6.2 不建议把账户层提前成当前重点

先把：

- 主策略
- 数据层
- 评估层

继续收口，优先级更高。

## 7. 映射到我们 4 条主策略

### 7.1 `trend_leader_unified`

最值得借：

- A 股本地数据组织
- 任务化扫描思路
- 市场识别与日历支持

### 7.2 `earnings_surprise`

主要借：

- 本地数据底座
- 交易日历与任务组织

直接策略逻辑帮助较弱。

### 7.3 `hundred_day_high`

很适合借：

- 市场与日历基础设施
- 任务化批处理思路

### 7.4 `monthly_slow_rise`

这条也适合借它的：

- 本地批处理组织
- 数据层与评估层支撑

## 8. 下一步是否值得做最小实验

值得，但更适合做基础设施小实验。

最合适的两个最小实验是：

1. 梳理一版更统一的 A 股市场/日历/代码语义层
2. 为本地策略补一层更清晰的任务化运行壳

## 9. 当前结论

`QUANTAXIS` 对我们最值钱的，不是新的主选股信号，而是下面 4 类能力：

1. A 股本地化数据与工具底座
2. 任务化、本地化运行组织
3. 统一账户与市场语义参考
4. 继续往性能与桥接层演进的工程思路

如果只用一句话概括：

- `QUANTAXIS` 最适合作为我们未来“A 股本地基础设施层”的参考对象，尤其能帮助数据、日历、任务和本地运行语义继续收口，但不适合作为当前 4 条主策略的直接替代品。
