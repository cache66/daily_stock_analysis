# vn.py 源码深挖记录
最后更新：2026-04-27

## 1. 仓库定位

`vn.py` 的公开定位非常稳定：它是一套成熟的 Python 量化交易框架与生态，不只是一个回测库，也不只是一个策略脚本仓库。

对我们最重要的判断是：

- 它最强的不是 A 股短线主选股策略答案
- 它最强的是模块边界、插件化生态、研究到执行的桥接能力
- 它最适合作为我们未来“结构分层、插件化组织、研究到执行边界”的参考对象

本轮结论基于 2026 年 4 月官方公开仓库与文档：

- 官方 GitHub 仓库：<https://github.com/vnpy/vnpy>
- 官方文档：<https://www.vnpy.com/docs/>

## 2. 核心结构与入口

本轮优先看的真实入口包括：

- 仓库主页 README
- 官方文档中的模块与应用说明
- `vnpy.alpha` 介绍
- 回测、组合、算法交易、风控、数据记录等应用说明

可以先把它理解成 5 层：

1. 核心基础设施层
   - 事件引擎
   - 网关
   - 数据库
   - 主程序框架
2. 应用插件层
   - CTA
   - 回测
   - 组合策略
   - 算法交易
   - 风险管理
   - WebTrader
3. 研究与因子层
   - `vnpy.alpha`
   - 数据集
   - 模型
   - 策略
   - lab
4. 数据与连接层
   - 行情
   - 历史数据
   - 交易接口
5. 用户工作台层
   - 桌面端
   - 图形化管理
   - 策略运行与监控

## 3. 真正的优点

### 3.1 它的模块边界非常清楚

vn.py 最值得借的，不是某个单点功能，而是它把一个量化系统拆得比较干净：

- 核心基础设施
- 插件应用
- 研究模块
- 连接器
- 工作台

这和我们当前很相关，因为我们现在正处于：

- 数据层
- 策略层
- 评估层
- 展示层

逐步分离的阶段。

### 3.2 它证明“研究层”和“执行层”可以共存但不混写

很多项目要么只做研究，要么只做交易。

vn.py 的价值在于：

- 研究层存在
- 回测层存在
- 执行层存在
- 这些层能并存，但边界比较清楚

这对我们非常重要，因为我们后面一定会面对一个问题：

- 本地策略继续增强时，研究逻辑和运行逻辑怎么避免混在一起

### 3.3 `vnpy.alpha` 值得重点看

README 和官方文档都说明，`vnpy.alpha` 已经把：

- dataset
- model
- strategy
- lab

作为明确组成部分。

而且它直接兼容 `Qlib` 的 `Alpha158` 数据集思路。

这说明 vn.py 不是只会做执行壳，它也在往研究层延展。

对我们来说，这个点很有价值，因为它比纯研究项目更贴近“研究结果如何接回工程系统”。

### 3.4 它的应用插件化比很多量化项目更成熟

官方文档里可以明显看到，它把很多能力都做成了相对独立的应用：

- 回测
- 组合策略
- 算法交易
- 风险管理
- WebTrader
- 数据记录

这对我们的直接启发是：

- 后面不应该一直让所有能力堆在主流程里
- 一些能力完全可以以“应用层”方式外挂

例如：

- 组合评估
- 信号复盘
- 专题解释

## 4. 我们能直接用的能力

### 4.1 把它当“模块边界参考对象”

这是它对我们最直接的价值。

特别适合服务我们的：

- 数据层继续收口
- 评估层逐步独立
- 工作台层和主策略层分离

### 4.2 借它的插件化组织方式

vn.py 很适合提醒我们：

- 不是所有功能都应该进入主选股循环
- 很多外围能力应该做成应用或插件

这和我们当前对本地策略的分层目标非常一致：

- 4 条主策略保留为主循环
- 其余观察、专题、解释能力降级为应用层

### 4.3 借它的“研究结果回接工程系统”思路

这点尤其适合后面服务：

- `earnings_surprise`
- `monthly_slow_rise`

因为这两条策略未来都需要：

- 更统一的因子层
- 更稳定的研究入口
- 与运行系统更清楚的衔接

### 4.4 给未来工作台层提供结构借鉴

vn.py 的桌面和应用生态说明，一套量化系统并不一定要把所有能力都糊在一个页面里。

对我们来说，这个提醒很关键：

- Signals 页面应更像主入口
- 专题、回测、解释、组合验证可以逐步做成独立工作台能力

## 5. 只适合参考、不建议直接接入的部分

### 5.1 不建议把 vn.py 当当前 4 条主策略的直接承载层

虽然 vn.py 很成熟，但它的强项仍然不是：

- 直接给出 A 股短线主选股逻辑

而是：

- 提供量化系统结构和应用生态

### 5.2 不建议现在就引入它的大量交易和连接生态

它的连接器和交易生态很重，而我们当前主要任务仍然是：

- 数据整理
- 策略质量
- 评估链路

### 5.3 不建议因为它有 `vnpy.alpha` 就弱化我们自己的 4 条主策略主线

`vnpy.alpha` 值得学的是：

- 研究层组织方式

不是替代我们当前主策略框架本身。

## 6. 不建议引入的部分

### 6.1 不建议整套搬运其插件生态

这会让当前系统复杂度快速抬升。

### 6.2 不建议过早把重点转向交易终端化

当前更重要的是：

- 主策略继续收敛
- 数据层和评估层继续清晰化

## 7. 映射到我们 4 条主策略

### 7.1 `trend_leader_unified`

最值得借：

- 插件化应用组织
- 后续组合与执行边界
- 工作台分层思路

### 7.2 `earnings_surprise`

很适合借：

- 研究层回接工程系统的方式
- `dataset / model / strategy / lab` 的组织思路

### 7.3 `hundred_day_high`

主要借：

- 模块边界
- 后续回测与应用层分离

### 7.4 `monthly_slow_rise`

这是比较适合借它的一条。

最值得借：

- 因子研究与运行系统衔接
- 中期策略在组合层和应用层的组织方式

## 8. 下一步是否值得做最小实验

值得，但更适合做结构实验，而不是接交易能力。

最合适的两个最小实验是：

1. 为本地策略补一层“应用化边界”
   - 主策略
   - 评估应用
   - 专题应用
2. 抽象一版更清楚的研究层目录
   - 为 `earnings_surprise / monthly_slow_rise` 服务

## 9. 当前结论

`vn.py` 对我们最值钱的，不是新的短线策略逻辑，而是下面 4 类能力：

1. 清楚的模块边界
2. 插件化应用生态
3. 研究层到执行层的桥接思路
4. 更适合长期演化的工作台组织方式

如果只用一句话概括：

- `vn.py` 最适合作为我们未来“结构分层和插件化工作台”的参考对象，尤其能帮助我们把研究层、评估层、运行层分开，但不适合作为当前 4 条主策略的直接替代品。
