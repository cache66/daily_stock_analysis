# 个人每日复盘约定

> 说明：这份文档只服务我个人在本仓库里的每日复盘口径，不属于原工程通用文档。

最后更新：2026-11-10（补双线工作台目标与旧 bundle 边界，现行参数不变）

本页 §2~§4 保留既有 fast-review bundle 的运行/阅读口径，其中冻结与启停以当前基线、冻结登记及代码为准。新工作台按[重构方案 §5](./个人投研工作台重构方案.md#5-页面重构每天打开要得到什么)组织：市场/板块变化、昨日强股今日表现、多种短线方法进展、长线公司变化、风险与到期待办；已有 HTML 原型尚未按本版改造。

## 1. 目标

每日复盘是“长线＋短线”的日常阅读入口：短线可按热点、股东户数、超跌、活跃量价等方法分别跟踪，长线看业绩、产业趋势与龙头逻辑的实质变化。默认呈现变化、原判断的后续和下一观察条件，不要求所有方法同一套筛选或每天重新填卡。

原 fast-review bundle 主要寻找下面两类票，其分组仍用于读取已有产物：

- 图形已经比较顺，同时业绩至少不差
- 业绩已经比较明确，图形开始启动或值得继续观察

这两类不是新增短线方法的统一准入。候选、信号、方法和前向有效样本分别计数；没有生产者、数据受限和健康零新增分别提示，完整失败样本继续保留。

## 2. 默认每日只跑什么

主入口：

```bash
python scripts/run_fast_review_bundle.py --strategy-profile-file config/local_strategy_profile.json
```

当前默认每日 `include_signals`（2026-09-27 起，三条）：

- `earnings` -> `earnings_surprise`
- `hundred_day_high`
- `trend_leader` -> `trend_leader_unified`

当前不进默认每日首页主筛：

- `daily_slow_rise`
  - 2026-09-27 按 ⑤ 判定（触发淘汰线）移出并冻结；脚本保留可按需单跑
- `long_base_release`
  - 2026-09-26 停用；脚本保留可手动单跑
- `monthly_slow_rise`
  - 保留为低频单跑
- 各类 `board/theme/dragon/snapshot/registry`
  - 归到专题或工具

## 3. 主文档怎么读

默认主汇总文件仍是：

- `fast_review_summary.md`
- `fast_review_stock_overview.csv`
- `fast_review_stock_overview.md`

但这份文件现在的角色是“每日精选复盘”，而不是“各策略文件索引页”。

新增的 `fast_review_stock_overview.*` 角色是：

- 单票证据总览
- 先看“这只票今天命中了哪些策略/证据”
- 再决定要不要回到各信号原始导出里深挖

主文档优先按这几个分组输出：

- `今日最值得看`
- `双确认候选`
- `图形优先候选`
- `业绩优先候选`
- `趋势补充观察`

其中：

- `双确认`
  - 同时有图形确认和业绩确认
- `图形优先`
  - 图形比较顺，业绩至少不差
- `业绩优先`
  - 业绩比较明确，但图形还在启动早期；如果预期仍是 `unknown`，至少要有价格、相对强度、资金画像或机构预期摘要里的一个确认
- `趋势补充`
  - 仅作为补充观察，不应该主导首页

现在默认阅读顺序也要固定下来：

1. 先看 `fast_review_summary.md` 顶部的“今日最值得看”
2. 再看 `fast_review_stock_overview.*`，确认每只票对应了几条策略证据
3. 只有需要追原始细节时，才回到各策略自己的 `csv/md`

## 4. 纯图观察票怎么卡

这里的“纯图观察票”，主要指首页里没有业绩确认、也没有 `hundred_day_high + daily_slow_rise` 双重图形确认，只能靠日 K 本身说话的样本，当前重点就是 `long_base_release` 这条线。

默认口径：

- 原始候选可以宽一点，首页阅读要更严一点
- 不满足图形质检的票，不一定从原始 `csv` 删除，但不应该继续占据 `每日精选复盘 -> 图形优先候选`

当前纯图质检重点看这几项：

- 最近 `20` 个交易日阳线占比至少约 `60%`
- 最近 `30` 个交易日阳线占比至少约 `58%`
- 最近 `5` 日不能明显转负
- 最近 `10` 日仍应保持一定延续，当前先按 `>= 5%` 理解
- 最近 `10` 日回撤不要太大，当前先按 `<= 10%`
- 最近 `10` 日连续阴线不要太多，当前先按 `<= 2`
- 最新价至少要站在 `MA10` 之上
- 最新交易日不能比 `snapshot_date` 明显过期；当前首页按“落后超过 `3` 天就不展示”处理，优先把停牌/长时间没更新的票挡掉

这套口径的目标很直接：

- 纯图票要“阳线多、趋势顺、最近没走坏”
- 原始策略可以继续为回查保留边界样本
- 首页只给更像“可以直接肉眼继续跟”的票

同时要注意一个实现口径：

- `daily_slow_rise / long_base_release` 这类图形票，不能只在“恰好和别的策略重叠”时才进单票视角
- 默认要先按股票聚合，再决定它是 `图形优先 / 业绩优先 / 双确认`

## 5. 后续修改护栏

以下约束主要适用于原 bundle；新工作台的多方法列表与详情按重构方案复用公共服务，不强塞进旧四类分组。共同遵守变化优先、来源可查、研究资格与交易权限分开的原则。本轮未改脚本或策略状态。

维护原 bundle 时继续遵守：

- 主文档优先只服务“人直接看”
- 不要在主文档顶部堆一排 `csv/md` 路径
- 原始 `csv/md/txt` 可以继续保留，但属于回查/调试资料
- 新策略先考虑归入这四类阅读语义，不要直接多开一个首页主分组
- 默认优先补“单票聚合层”，不要继续把同一只股票拆散到多个互相独立的策略首页里
- 对 `earnings-only` 票，首页和单票总览默认要更严：
  - 不能只因为财报分数过线就展示
  - `fast_review_focus_gate_passed=true` 只代表过了最低快复盘门槛，不代表自动进入首页
  - 至少还要看到一部分“市场愿意继续看”的确认，例如：
    - 增速足够
    - 业绩质量不差
    - 周期阶段不是明显 `mixed/mature`
    - 资金画像 / 相对强度 / 机构预期里至少有一项不太差
- 如果 `trend_leader` 再次回到默认首页，必须明确说明为什么它比图形主筛更重要
- 如果继续放宽 `long_base_release` 原始阈值，必须同时检查首页纯图质检是否仍能把“停更 / 走坏 / 高位钝化”的票挡在前排之外
- 全市场快扫的 `Tushare` 限流必须按“进程级共享”理解，不能让多个 `TushareFetcher` 实例各自按 45/min 记账后叠加撞上账号侧 `50/min`
- `Tushare` 对部分次新股/新股窗口返回空历史时，不能直接掐掉 `Akshare` 回退；这类 `no data` 需要保留二次尝试空间

## 6. 推荐维护顺序

涉及每日复盘收口时，优先同步：

1. `scripts/run_fast_review_bundle.py`
2. `config/local_strategy_profile.json`
3. 本文档
4. `个人策略基线.md`
5. `个人策略目录.md`
6. `个人策略修改记录.md`
7. `docs/CHANGELOG.md`
