## 0. 背景与目标

当前问题：

- Web `/personal-strategies` 已挂 **14 条策略**，但日常真正在跑的只有 4 条默认主链路；
- 策略相关脚本约 **36 个**（`select_*` ×12、`collect_*` ×7、shortline 家族 ×11、散件 ×7），多数自 2026 年 4-5 月起没有任何运行产物；
- `docs/个人策略文档/` 合计约 **1.3 万行**（其中修改记录 10,423 行、目录 1,677 行），日常检索和维护成本已偏高。

目标形态：回到《个人每日复盘约定》的初衷——**每日复盘优先服务"图形 + 业绩"**，把系统收口为：

1. 每天固定跑的 **4 条核心**；
2. 按需跑的 **2 条低频**；
3. **1 个观察池**工具；
4. 其余专题与散件登记**冻结**，不再投入维护。

基本原则：

- **冻结 ≠ 删除**：代码与 git 历史全部保留，随时可复活；
- 先文档、后代码；每一步独立提交、可单独回滚；
- 不改变每日四信号的现有行为与 Web 读层产物结构。
