## 2. 候选逐项

### 2.1 chan.py —— 缠论结构计算（2.2k★，MIT）

- 定位：开放式缠论 Python 实现：分形 / 笔 / 线段 / 中枢 / 买卖点，多级别联立、区间套，绘图（matplotlib），数据接入 akShare / baostock / futu。
- 值得借：给图形两条线（`daily_slow_rise` / `trend_leader`）加一个**结构视角**——把"30-45 度慢涨 / 平台转趋势"翻译成"笔、段、中枢的抬升关系"，与现有纯数值特征互补。
- 注意：README 明确公开版为完整版子集（完整版约 2.2 万行、公开约 5.3 千行），策略 / 特征 / 模型 / 交易引擎部分以 demo 为主；作者自述"不必是（教科书意义的）真正缠论"。→ 当作**结构计算库**用，不接其交易系统。
- 成本：只读 0.5h；小样本试用（10 只票标注结构、对照现有信号）约 2~4h。
- 抓取时点：最近提交约 3 个月前。

### 2.2 hikyuu —— 高性能系统交易框架（3.5k★，Apache-2.0，C++ / Python）

- 定位：C++ 核心 + Python 绑定的系统交易框架；把策略拆成**可替换组件**——市场环境 EV / 条件 CN / 信号 SG / 止损止盈 ST / 资金管理 MM / 盈利目标 PG / 滑点 SP / 组合层（PF / SE / AF / MF）/ TradeManager；数据层支持 HDF5 / MySQL / ClickHouse / SQLite；自带 `hikyuu.interactive` 交互探索与指标绘图；A 股数据一键导入（HikyuuTDX）。
- 项目状态：**高度活跃**（抓取当日仍有提交；最新 release 2.8.2；正在做英文化与 i18n）。
- 值得借：① "系统交易组件拆分"的完整参照——如果将来给个人系统做"卖出 / 风控组件"（止损、止盈、资金管理、组合分配），它的组件边界是现成教材；② 指标 / 公式层与 TA-Lib 集成、numpy / pandas 互操作；③ 性能工程参考（全市场 1913 万根日 K，预热后 166ms 求和）。
- 注意：完整框架引入成本高，且触碰"不引第二套回测 / 交易体系"红线 → **只读不引**；它的数据层与界面偏重仓，与现有 `DataFetcherManager` 不互通。
- 成本：按需选读（先读 README 的「Core parts of the systematic trading architecture」一节，0.5h）。

### 2.3 zvt —— 模块化 A 股框架（4.3k★，MIT）

- 定位：数据（东财 / 新浪 / 聚宽等多 provider）→ 实体-事件模型 → 因子（`data_df / factor_df / result_df` 三段式）→ TargetSelector → trader 回测 → Dash / REST UI（`zvt_ui`）。
- 值得借：因子层与选股层的**组织范式**；多数据源互为备份的设计（与我们 `DataFetcherManager` 多源思路同源）。
- 注意：作者声明"不保证向后兼容"；抓取时点最近提交约 3 个月前、最新 release v0.13.5（约 8 个月前）→ 维护放缓，**读思路不引依赖**。
- 成本：对照阅读半天。

### 2.4 因子素材：Alpha101 / 国泰君安 191

- 定位：WorldQuant《101 Formulaic Alphas》+ 国泰君安 191 短周期价量因子（社区实现较多，无权威单一仓库）。
- 值得借：P1 因子检验的**候选因子池**；针对"评分排序 RankIC≈0"这类结论，可直接拿现成因子在现有评估器口径下做增量测试。
- 注意：选用时以论文 / 研报对照 + 高星实现为准，逐个验证口径（复权、窗口、去极值）。
- 成本：材料通读 1~2h；挑 10~20 个因子试跑约 1 天。

### 2.5 alphalens-reloaded —— 因子评估（657★，Apache-2.0）

- 定位：Quantopian alphalens 的社区维护分支（stefan-jansen 维护；原版已归档）；输入"因子值 + 价格"，输出收益 / IC / 换手 / 分组 tear sheet。
- 值得借：**不上 qlib 时的轻量因子检验**；数据无缝（本地缓存直接喂），输出现成。
- 注意：生态偏 zipline / pyfolio 系；只用分析函数即可；更新节奏平缓（v0.4.5）。
- 成本：半天出第一版 IC 报告。

### 2.6 quantstats —— 绩效报表（7.7k★，Apache-2.0）

- 定位：组合绩效分析三件套（`stats` / `plots` / `reports`）+ HTML tearsheet + Monte Carlo。
- 值得借：`leaderboard` 与复盘导出的**报表增强**（回撤细节、月度热图、滚动 Sharpe）。
- 注意：指标口径是 period-based（按周期收益，不是按笔），与决策日志"按窗口"口径不同维，引用时标注。
- 抓取时点：**当日仍有提交**，维护活跃。

### 2.7 ML4T（Machine Learning for Trading 第 3 版）（21k★）

- 定位：Stefan Jansen 书配套仓库：27 章 + 9 个 case study + 6 个生产库（ml4t-data / engineer / models / diagnostic / backtest / live）+ 112 primers + 61 agent skills；Polars + Docker 环境。

- 注意：美股向、体量大（环境约 16GB）；按章选读，不整体引入。

## 3. 策略思想参考（与四条线一一对应）

> 这部分不是代码，而是"为什么这些线可能有效"的文献锚点；用于复盘与判读，不直接产生信号。

- **业绩线** ← PEAD（盈余公告后漂移：Ball & Brown 1968；Bernard & Thomas 1989）+ SUE（标准化超预期）→ 可指导"超预期强度 → 持有窗"的分层设计。
- **新高线** ← 52 周新高效应（George & Hwang 2004）→ "新高本身"有独立 alpha 的解释。
- **趋势线** ← 时序动量 TSMOM（Moskowitz, Ooi & Pedersen 2012）+ 动量崩溃（Daniel & Moskowitz 2016）→ 风控语境。
- **慢涨线** ← Minervini VCP / CANSLIM（O'Neil）→ VCP 收缩形态可作增量特征（现有 `minervini_template_score` 的延伸）。
- **双确认（业绩 + 新高）** ← PEAD × 52 周新高交叉的增量证据（文献线索，待核）。
- **防守 / 备用** ← QMJ（Asness, Frazzini & Pedersen）、Piotroski F-Score（2000）、Dual Momentum（Antonacci）→ 与股息线 ma200 闸门同源。

### 6.3 ML4T 首轮选读要点（2026-09-26）

选读 3rd edition（21k★，快速迭代中；章节目录与 2nd edition 不同，以下为当前版）。与我们直接相关的是“证据纪律 + 防过拟合”两条线：

### 6.4 F2 预热：免费阅读路径（2026-09-26 核实）

ml4trading.io 的 primer 可免费浏览（索引与多数页面无需注册），与 F2 / F1 直接相关的 5 页已核实存在：

- *Multiple Testing and the Researcher's Trap* —— “搜得多 → 假发现必然多”的问题定义（PBO / DSR 的出发点）；
- *Sharpe Ratio: Definition, Annualization, and Estimation Noise* —— 回测 Sharpe 的估计噪声（短样本 Sharpe 会被 trials 放大）；

- *Momentum and Mean Reversion* —— 动量/反転的期限结构（与 trend / dsr 线判读相关）。

F2 启动顺序（与 §6.3 对齐）：先读上面 1+2 两页 → Ch7（BH-FDR + DSR 定义与用法）→ Ch16（DSR / Rademacher / White's Reality Check 工具箱）；需要参考实现时再读 `ml4t-diagnostic` 源码（只读）。

### 6.5 hikyuu / zvt 只读备忘（2026-09-26）

**hikyuu（3.5k★，Apache-2.0，当日仍在提交）——借用“组件边界与命名”（未来卖出 / 风控组件设计参照）：**

- 交易系统 SYS = **EV**（市场环境有效性）+ **CN**（适用条件）+ **SG**（买卖信号）+ **ST**（止损止盈）+ **MM**（头寸/资金管理）+ **PG**（盈利目标）+ **SP**（滑点模拟）；
- 组合层 = **PF**（策略调度）+ **SE**（系统筛选）+ **AF**（资金分配）+ **MF**（多因子打分排序）；
- 交易管理 = **TM**（账户/持仓记录）+ **OB**（实盘通道）；数据层 = StockManager / KData / Query。
- 对我们：四条线目前只有 “SG（信号）” 一个组件；将来若引入退出机制，ST + PG + MM 三个边界可直接对齐命名，**不引代码**（C++ 核心 + HDF5 数据层与现有体系不互通）。性能基准（1913 万根 K 线求和 166ms）可作未来性能工程参考。

**zvt（4.3k★，MIT，维护放缓：最新提交 3 个月前 / v0.13.5 8 个月前）——借用“三段式组织”：**

- `data_df`（原始行情）→ `factor_df`（transformer 计算）→ `result_df`（filter_result / score_result，供 TargetSelector）——把“因子计算”与“结果筛选”显式分层；
- 对照我们现状：快照 → 评估器 → leaderboard 是一体式脚本串联；F1 做因子台账时，可借用“一个因子 = 一个 transformer + 一个 result 列”的命名习惯保持可组合性；
- 其 `record_data(provider=...)` 增量更新 + provider map 与 `DataFetcherManager` 多源思路同源，**不引依赖**。
