# 股东户数筹码集中筛选方法

> 记录时间：2026-10-31 · 数据期：2026 三季报（截止日 2026-09-30，部分个股更新至 2026-10-30）
> 用途：判断「筹码是否真的集中到底」，而不是只看"从最高降了多少"。

## 1. 为什么要这个指标

股东户数下降 = 持股人数减少 = 单个股东平均持股增加，常被当作「筹码集中 / 主力吸筹」信号。
但**只看"从最高降幅"会误判**：某只票从 100 万户降到 60 万户（-40%）看起来集中得不错，
如果它历史上最集中到过 30 万户，那现在其实还在半山腰。

所以本方法的核心是**历史位置**，不是降幅。

## 2. 口径定义

以近 **16 个季末**（约 4 年）为历史窗口：

```
pos        = (当前户数 − 近4年最低) / (近4年最高 − 近4年最低)
              pos → 0  已贴到近4年最集中
              pos → 1  近4年最分散
距底部空间 = 当前户数 / 近4年最低 − 1        ← "还能降多少"
底部距今季度 = 最低点日期 → 最新报告期 的季度数
仍在下降    = 最新一期 < 上一期
连续下降次数 = 从最新一期往回数，连续减少的期数
```

**三个维度必须一起看**：

| 维度 | 含义 | 为什么重要 |
|---|---|---|
| `pos` | 相对位置的绝对值 | 判断是否真的到底，而不是降幅好看 |
| `底部距今季度` | 底部新鲜度 | 底部在 3 年前 = 参考价值低（如圣邦股份 pos 低但底部在 2023-12，距底部还有 99%） |
| `仍在下降` | 当前是否还在集中 | 停止下降可能意味着集中完成，也可能意味着趋势反转 |

## 3. 数据源

| 用途 | 接口 | 说明 |
|---|---|---|
| 历史季度快照 | `ak.stock_zh_a_gdhs(symbol="20250930")` 等 | 每期返回「本次 + 上次」两列，抓 16~31 期即可拼出长历史；北交所在 83/87/92 段 |
| 每股最新快照 | `ak.stock_zh_a_gdhs(symbol="最新")` | 5,577 行，**1,028 只比季报更新**（回购/公告自愿披露），最晚到 10-30 |
| 三季报业绩 | `ak.stock_yjbb_em(date="20260930")` | 见 `yjbb_20260930_a_share.csv` |
| 本地缓存 | `data/strategy_review/earnings_events_raw/_gdhs_hist_cache.pkl` | pickle，避免每次重拉 31 期 |

**新鲜度上限**：季报节点（3-31 / 6-30 / 9-30 / 12-31）是主数据；月中（尤其 10-20 前后）会有一批公司主动披露。

## 4. 五个数据坑（踩过，必须过滤）

1. **新股上市初期异常低值** —— 历史最低出现 2、4、7 户这类记录，会把 `pos` 和「距底部空间」彻底算错。
   → 过滤 `近4年最低 < 1000 户`，且要求历史点数 ≥ 12。
2. **银行 / 证券 / 保险 / 多元金融** —— 户数因机构化长期结构性下降，不代表筹码集中。
   → 整类剔除。
3. **ST / *ST** —— 退市风险、暴跌导致户数骤降，"假集中"，榜首常被这类占满。
   → 剔除名称含 ST。
4. **陈旧样本** —— 停牌 / 未披露的公司，"最新一期"还停在几个月甚至几年前。
   → 要求 `当前截止日 >= 报告期`（本次为 2026-09-30）。
5. **截止日不一致** —— 个股当前值可能来自不同日期（9-30 / 10-09 / 10-20 / 10-30）。
   → 输出必须带 `当前截止日` 列，横向比较时注意。

## 5. 分层口径

| 档位 | 条件 | 含义 |
|---|---|---|
| **一档** | 底部距今 ≤4 季 · `pos ≤ 0.2` · 仍在下降 · 净利同比 > 0 · ROE > 5 · 净利 > 0 | 刚到底 + 还在集中 + 业绩不差 |
| **二档** | `pos ≤ 0.2` · 已停止下降 · 业绩正增长 | 集中完成，转为观察池 |
| **三档** | `0.2 < pos ≤ 0.35` · 仍在下降 · 业绩正增长 | 差一口气，等下一期 |
| **陷阱名单** | 从最高降幅 ≤ -35% 但 `pos ≥ 0.5` | 看着降得多，其实离底部还很远 |

## 7. 复现步骤

```bash
# 1) 拉季度历史（首次约 31 次请求，之后走 pickle 缓存）
# 2) 拉「最新」表覆盖当前值（1 次请求）
# 3) 合并三季报业绩 → 算 pos / 底部距今 / 连降 → 分层
# 4) 输出 CSV
```

## 9. 已知局限

1. `pos` 是**相对位置**，不是「还有多少下行空间」；若个股持续创新低，`pos` 会一直是 0。
2. 户数下降 ≠ 主力吸筹。也可能是散户割肉离场、被套不管。必须叠量价与户均市值验证。
3. 月度数据覆盖不全（仅主动披露的公司），不能拿来做全市场横向比较。
4. 季报数据滞后最多 1.5 个月（9-30 数据，10 月中旬才齐）。
