# 进攻线每日运行手册

> 状态：2026-09-25 建立。适用：进攻线（百日均线突破 / 短线慢涨 / 长底突破 / 趋势龙头）单人多机日循环。
> 目的：把「跑完产线但结论没用」变成每天 10 分钟内的固定四步——**图形筛人 → 催化定题 → 聚合看主线 → 框架出结论**。

## 0. 前提与心理模型

- 本线是**进攻性观察线**，不是自动交易信号：产出是「今天值得人工看哪几只、哪条题材在发酵」。
- 所有选股/行情取数统一走 `DataFetcherManager` / `KlineSelectorService`（见 [`数据与验证统一约定.md`](./数据与验证统一约定.md)）。
- 市场状态（regime）控页面可见策略：默认 `defensive`（只出 4 条进攻策略）；要放开 earnings 策略请改 `config/local_strategy_profile.json` 的 `market_regime` 为 `balanced`。
- 冻结的 8 条策略与脚本不参与日循环（见 [`策略与脚本冻结登记.md`](./策略与脚本冻结登记.md)）。

## 1. 四步日循环（收盘后执行）

### Step 1 全市场产线（数据与矩阵）

```bash
./.venv-linux/bin/python scripts/run_personal_strategy_matrix.py \
  --snapshot-date latest --log-level INFO
```

- 产物：`data/manual_runs/personal_strategy_matrix/<日期>/review/fast_review_stock_overview.csv`
- 检查点：CSV 里 `cycle_catalyst_label` / `theme_label` / `cause_tags_zh` 非空的行数（催化命中情况）。
- 冷启动慢时先冒烟：`--bundle-limit 300 --skip-prewarm`，确认链路后再全市场。
- 取数提速可调 `TUSHARE_SELECTOR_RATE_LIMIT_PER_MINUTE`（默认 35，账号档位允许时可到 45；改 `.env` 后重启运行即可生效）。
- 百日新高默认开启归因（profile `hundred_day_skip_cause_analysis=false`），候选会带 `cause_tags/theme_label`；若临时关掉，短线观察交集会退化。
- 期末（非财报窗口）earnings 线可能 0 候选（`recent-event prefilter` 把 universe 缩到个位数），属正常现象，不用排障。

### Step 2 短线观察（图形件）

```bash
./.venv-linux/bin/python scripts/run_short_term_watch.py \
  --snapshot-date latest --top 10 --graph-only-top 8
```

- 产物：`data/short_term_watch/<日期>/short_term_watch.csv|md`
- 读法：**图形 ∩ 催化** 命中优先；其次看 graph-only 名单（图形好但尚无催化，等题材）。
- 命中字段来源：`cycle_catalyst_type`（内置产业催化）/ 观察清单关键词（`config/catalyst_watchlist.json` 的 AI算力、存储涨价、机器人，自行维护增删）。

### Step 3 题材/催化聚合（看主线）

```bash
./.venv-linux/bin/python scripts/run_catalyst_digest.py --snapshot-date latest --top 12
```

- 产物：`data/catalyst_digest/<日期>/catalyst_digest.md|json`；跨日历史 `data/catalyst_digest/history.jsonl`（按日期幂等更新）。
- 读法：
  - 「连续 ≥2 天」= 主线候选（同一题材连续上榜，比单日热点可靠）；
  - `Δ昨日` 为正 = 今日在扩散；
  - 「其中图形」>0 = 题材里已有图形确认的个股（可以人工细看）。
- 首次运行历史为空时全部 `连续=1`，跑几天后才有参考价值。

### Step 4 框架 LLM 出结论（人工复核）

把 Step 2/3 的焦点代码交给框架主流程出个股报告：

```bash
./.venv-linux/bin/python main.py --stocks 002463,300476,002025
```

- 报告遵循框架既有通知/报告链路（详见 [`full-guide.md`](../../full-guide.md)）。
- 本线只负责**给出候选与题材上下文**；买不买、买多少仍走人工复核，不要用本线代替风控。

## 2. 结果不理想时的排查顺序

1. Step 1 产物是否刷新（`ls data/manual_runs/personal_strategy_matrix/<日期>/review/`）。
2. 矩阵 items 是否带 `cycle_catalyst_*` 字段（API `/api/v1/signals/personal-strategy-matrix` 或 CSV 直接看）。
3. 短线观察的交集为空 → 看 digest 是否有「图形件」列 >0 的题材（有=催化在题材层而非个股层，属正常）。
4. 题材全为空 → 上游 bundle 未产出催化文本（检查产线 `--log-level INFO` 日志与 `cause_tags_zh` 列）。
5. 概览 CSV 里 5 个催化字段（`cycle_catalyst_*`/`theme_label`/`cause_tags_zh`/`mainline_judgement`/`preferred_industry_label`）全空 → 当日产物**未跑产业催化分析**（profile 的 `*_skip_cause_analysis` 或注册表未接入），此时交集=0 属预期、不是 bug；要「图形∩催化」有意义需开启 cause 分析或依赖人工清单。
6. regime 是否卡在 `defensive`（页面只显示 4 条策略属预期）。

## 3. 维护约定

- `config/catalyst_watchlist.json`：关键词清单是**主观增强**，只做加权不做硬过滤；过期条目可删（`expires_on` 仅作提醒，不自动失效）。
- 修改本线代码后至少跑：
  ```bash
  ./.venv-linux/bin/python -m pytest -q \
    tests/test_personal_strategy_matrix_service.py \
    tests/test_short_term_watch_service.py \
    tests/test_fast_review_focus_api.py \
    tests/test_personal_strategy_run_service.py \
    tests/test_catalyst_digest_service.py \
    tests/test_fast_review_catalyst_mapping.py
  ```
- 新增/修改脚本产出路径变化时，同步更新本手册与 [`个人策略修改记录.md`](./个人策略修改记录.md)。
